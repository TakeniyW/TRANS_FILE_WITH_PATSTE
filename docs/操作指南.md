# ClipFile 操作指南

> 适用版本：v1.0.0
>
> 本文面向实际使用者，说明发送端与接收端的完整操作步骤、断点续传方法和必须注意的风险点。开发与协议说明见 [README](../README.md)。

## 1. 准备工作

### 1.1 获取工具

方式一：使用打包好的单文件程序（推荐）

- 云桌面内使用 `send_tool.exe`
- 本地桌面使用 `recv_tool.exe`
- 两个 exe 需在 Windows 上执行 `build.bat` 自行生成（仓库不提交二进制）

方式二：使用源码运行（需要 Python 3.9+）

```bash
python send_tool.py   # 云桌面
python recv_tool.py   # 本地
```

### 1.2 传输前确认

| 检查项 | 要求 |
|---|---|
| 剪贴板同步 | 云桌面与本地之间可以复制粘贴纯文字（先复制一段中文到本地验证） |
| 工具权限 | 发送端能读取目标文件；接收端能写入保存目录 |
| 磁盘空间 | 本地保存目录至少预留“文件大小 × 2”的空间（分片缓存 + 最终文件） |
| 文件状态 | 传输期间不要修改、移动或重命名源文件 |
| 分片大小 | 默认 512 KB；若剪贴板同步经常截断，改用 128 KB 或 256 KB |

> 建议先启动接收端监听，再启动发送端发送第 1 片，避免首片在接收端启动前被覆盖。

## 2. 快速上手（推荐：自动模式）

| 步骤 | 云桌面（发送端） | 本地桌面（接收端） |
|---|---|---|
| 1 | 打开 `send_tool.exe` | 打开 `recv_tool.exe`，选择保存目录 |
| 2 | 点击“选择文件”，等待 SHA-256 计算完成 | 点击“开始监听”，按钮变为“停止监听” |
| 3 | 根据需要选择分片大小（默认 512 KB） | 保持“收齐后自动合并”勾选 |
| 4 | 勾选“自动连续发送”，间隔设为 3–5 秒 | 观察进度、片数和字节数变化 |
| 5 | 等待全部片发送完毕 | 收齐后自动合并，弹出“SHA-256 校验通过” |

自动模式依赖剪贴板同步的实时性。如果接收端出现缺片，先停止自动发送，按第 5 节补发即可。

## 3. 发送端使用教程

### 3.1 界面说明

| 区域 | 作用 |
|---|---|
| 文件 / 选择文件 | 选择待传输文件，工具自动计算大小、SHA-256 和总片数 |
| 分片大小 | 128 KB / 256 KB / 512 KB / 1 MB，默认 512 KB |
| 文件信息 | 显示文件名、原始大小、完整 SHA-256、总片数 |
| 当前片 | 显示“第 X / N 片”和本片大小 |
| 上一片 / 发送当前片 / 下一片 | 导航并发送指定分片 |
| 自动连续发送 | 每隔 N 秒自动发送下一片，发送完最后一片后自动停止 |
| 日志 | 记录每次发送的片号、大小和状态 |

### 3.2 手动逐片发送

1. 点击“选择文件”，选中目标文件。
2. 确认“文件信息”中的大小和总片数正确。
3. 点击“发送当前片到剪贴板”，日志会提示“已复制第 X/N 片”。
4. 切换到本地接收端完成接收（推荐接收端保持“开始监听”状态）。
5. 回到发送端点击“下一片”，再点击“发送当前片到剪贴板”。
6. 重复直到第 N 片发送完成。

> “上一片”用于补发。接收端对重复片会自动忽略，不会重复追加。

### 3.3 自动连续发送

1. 选择文件并确认总片数。
2. 在“间隔”中填入秒数（建议 3–5 秒，需大于剪贴板同步延迟）。
3. 勾选“自动连续发送”。

工具会立即发送当前片，然后每隔设定秒数自动前进并发送下一片；全部发送完毕后自动取消勾选。若中途需要暂停，取消勾选即可。

### 3.4 发送端断点恢复

发送位置会记录在 `%USERPROFILE%\.clipfile\sessions\`（可用环境变量 `CLIPFILE_HOME` 修改根目录）。重新打开工具并选择同一文件时：

- 文件大小、修改时间、分片大小均未变化，则自动恢复到上次发送位置；
- 修改过分片大小或文件已变化，则从第 1 片重新开始；
- 恢复后请核对界面显示的片号，再继续发送。

## 4. 接收端使用教程

### 4.1 界面说明

| 区域 | 作用 |
|---|---|
| 保存目录 | 最终文件与临时分片的存放位置，默认“下载”或用户主目录 |
| 接收信息 | 文件名、原始大小、总片数、已接收片数 |
| 进度条 / 百分比 | 已接收片数占总片数的比例 |
| 已接收 X / Y 片 | 当前进度和已接收字节数 |
| 开始监听 / 停止监听 | 每秒自动检查剪贴板并接收新分片 |
| 接收当前片 | 手动读取一次剪贴板 |
| 合并保存 | 手动触发合并；未收齐时会提示缺少的片号 |
| 收齐后自动合并 | 默认勾选，全部分片到齐后自动校验并保存 |
| 日志 | 接收、重复、缺片、校验和保存结果 |

### 4.2 自动监听模式（推荐）

1. 点击“选择目录”，选择本地保存位置。
2. 点击“开始监听”。
3. 保持窗口打开，工具每秒读取一次剪贴板：
   - 内容不是协议文本：静默忽略，不影响接收；
   - 片号已存在且 CRC 一致：忽略重复片；
   - 缺失片号：在状态栏显示缺少片数，点击“合并保存”可查看具体片号范围。
4. 全部分片收齐后，自动合并、校验 SHA-256 并保存。

### 4.3 手动接收模式

1. 选择保存目录。
2. 在云桌面发送一片后，回到本地点击“接收当前片”。
3. 重复“发送 → 接收”，直到收齐。

手动模式下如果忘记点击，接收端不会自动接收；已接收的进度不会丢失。

### 4.4 断点续传

接收进度保存在 `<保存目录>/.clipfile_temp/`：

```text
<保存目录>/
└── .clipfile_temp/
    ├── session.json        # 文件名、大小、SHA-256、总片数、已收片记录
    └── parts/
        ├── 000001.bin      # 解码后的第 1 片
        ├── 000002.bin
        └── ...
```

中断后重新打开接收端时：

1. 选择**同一个保存目录**；
2. 日志出现“检测到未完成会话”，界面恢复已接收片数；
3. 继续监听并让发送端补发剩余分片；
4. 收齐后自动或手动合并。

> 更换保存目录不会带走旧进度。请务必选择原目录，或手动把整个 `.clipfile_temp/` 复制到新目录。

### 4.5 合并与校验

- 所有分片到齐后，工具按片号顺序拼接，再次校验每片 CRC32；
- 校验合并后文件的大小和整文件 SHA-256；
- 通过后保存为原始文件名；若同名文件已存在，自动命名为 `文件名 (1).扩展名`，不会覆盖；
- 成功后自动删除 `.clipfile_temp/`。

## 5. 典型场景

### 5.1 补发缺失片

1. 接收端点击“合并保存”，弹出的对话框会给出缺失片号，例如 `5, 9-11`；
2. 在发送端用“上一片 / 下一片”导航到对应片号；
3. 点击“发送当前片到剪贴板”；
4. 接收端自动监听或点击“接收当前片”；
5. 补齐后再次合并。

### 5.2 校验失败

出现“整文件 SHA-256 校验失败”时：

- 临时分片会保留，不会删除；
- 常见原因是源文件在传输过程中被修改，或某个分片内容异常；
- 先确认源文件未被改动；必要时重新发送可疑分片，或从第 1 片重新传输；
- 仍失败时，删除保存目录下的 `.clipfile_temp/` 后重新开始。

### 5.3 同一目录传输另一个文件

如果日志提示“该目录存在另一文件的未完成会话”，说明目录中还有未完成的旧任务：

1. 优先完成旧任务；或
2. 更换保存目录；或
3. 确认旧任务不再需要后，关闭接收端，删除该目录下的 `.clipfile_temp/`，再重新开始。

### 5.4 同一个文件传两次

接收端会保留两份文件，第二份自动加 ` (1)` 后缀。若只想保留一份，请删除旧文件或更换保存目录。

## 6. 注意事项

### 6.1 剪贴板相关

- **传输期间不要复制其他文字**，否则会覆盖当前分片，导致该片丢失。
- 剪贴板文本被截断时，表现为接收端解析失败或始终收不齐。请把分片大小调小（建议 128 KB），并确认剪贴板同步工具未设置长度限制。
- 云桌面策略若完全禁止复制纯文本，本工具无法工作。
- 自动模式要求剪贴板同步延迟小于发送间隔；建议间隔 3–5 秒，不要设置过小。
- 接收端只读剪贴板，不会反向写入，不会影响发送端内容。

### 6.2 文件与校验

- 发送端只读取源文件；传输期间修改源文件会导致最终 SHA-256 校验失败。
- 每片使用 CRC32 校验，整文件使用 SHA-256 校验；不要手工编辑协议文本。
- 文件名支持中文和空格；保存时会清理路径分隔符等非法字符，防止目录穿越。
- 空文件也可以传输（按 1 片处理）。

### 6.3 目录与缓存

- `.clipfile_temp/` 是断点续传的关键，传输完成前不要删除、移动或重命名。
- 保存目录需要至少“文件大小 × 2”的可用空间。
- 传输成功后临时目录会自动清理；校验失败时会保留，便于补发。
- 发送端只写入自己的进度记录目录，不修改源文件所在目录。

### 6.4 容量与性能

- 默认单文件上限 500 MB；发送端和接收端的环境变量必须同时调整，否则接收端会拒绝超限文件：

```bat
set CLIPFILE_MAX_FILE_SIZE=1073741824
```

- 分片越小，剪贴板越稳定，但总片数和操作次数越多；分片越大，单次复制风险越高。
- 大文件建议使用自动模式；接收端内存占用只与单片大小相关，不会加载整个文件。
- 传输前确认本地磁盘剩余空间充足，避免合并阶段因空间不足失败。

### 6.5 安全

- 工具不发起任何网络连接，不上传任何数据。
- 发送端只读取用户选择的文件，并写入本机进度记录；接收端只写入用户选择的目录。
- 从非官方渠道获取的 exe 存在被替换风险，建议使用仓库源码或自行执行 `build.bat` 打包。
- Windows SmartScreen 可能对未签名 exe 提示风险，确认来源后可选择“仍要运行”。

## 7. 常见问题排查

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| 发送后本地粘贴不到内容 | 剪贴板同步未开启或策略限制 | 先用普通文字验证双向复制 |
| 接收端一直 0 片 | 文本被截断、不是协议文本、未点击开始监听 | 调小分片；确认文本以 `===CLIPFILE===` 开头；点击“开始监听” |
| 提示“尚未收到首片” | 第 1 片丢失或接收端启动过晚 | 在发送端导航到第 1 片重新发送 |
| 提示“总片数不一致” | 剪贴板中混入了其他文件的分片 | 重新发送当前文件的第 1 片，或更换保存目录 |
| 提示“另一文件的未完成会话” | 保存目录存在旧任务 | 完成旧任务、更换目录或清理 `.clipfile_temp/` |
| 一直缺少固定几片 | 这些片被覆盖或未成功复制 | 按提示片号补发 |
| SHA-256 校验失败 | 源文件被修改、分片异常 | 保留的临时分片可补发重试；仍失败则清理后重传 |
| 合并失败提示空间不足 | 磁盘空间不够 | 清理空间后点击“合并保存” |
| exe 无法启动 / 被杀毒拦截 | 未签名程序 | 添加信任或使用源码运行 |
| 中文文件名异常 | 使用了旧版本 | 使用当前版本，协议已对文件名做百分号编码 |

## 8. 配置参数速查

| 参数 | 位置 | 默认值 | 说明 |
|---|---|---|---|
| 分片大小 | 发送端界面 | 512 KB | 可选 128 KB / 256 KB / 512 KB / 1 MB |
| 自动发送间隔 | 发送端界面 | 3 秒 | 1–60 秒，建议不小于剪贴板同步延迟 |
| 单文件上限 | 环境变量 `CLIPFILE_MAX_FILE_SIZE` | 500 MB | 两端需同时设置 |
| 发送端进度目录 | 环境变量 `CLIPFILE_HOME` | `~/.clipfile` | 存放发送位置记录 |
| 接收端临时目录 | 保存目录下 | `.clipfile_temp/` | 存放 `session.json` 与分片 |
| 接收端轮询间隔 | 固定 | 1 秒 | 自动监听模式 |

## 9. 传输完成自检清单

- [ ] 接收端进度显示“已接收 N / N 片”
- [ ] 弹出“传输完成，SHA-256 校验通过”
- [ ] 保存目录中存在原始文件名
- [ ] 文件大小与发送端显示一致
- [ ] `.clipfile_temp/` 已自动删除
- [ ] 打开文件抽查内容可正常使用

如任一项不满足，请保留现场（不要删除 `.clipfile_temp/`），按第 7 节排查。
